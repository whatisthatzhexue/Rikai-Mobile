## 2. `lib/` 四层

| 层 | 文件数/行数 | 职责 | 依赖规则 |
|---|---:|---|---|
| `lib/core/` | 43 / 6,824 | 纯模型、主题、通用 UI、工具 | 不依赖 `services/state/features` |
| `lib/services/` | 85 / 21,259 | Agent、MDict、MeCab、OCR、存储、查词、安全 | 不导入 `features/state`，不依赖 Flutter UI |
| `lib/state/` | 13 / 3,525 | 全部 Riverpod provider/controller | 可依赖 core/services |
| `lib/features/` | 55 / 18,643 | 页面与 widget | 可依赖 core/state/services |
| 根 | 3 / 445 | `main.dart`/`bootstrap.dart`/`app.dart` | 组合根/路由 |

> 文件数/行数为 2026-11-11 盘点值（共 199 文件 / 50,696 行）；当前测试/构建数值见 `01-规范/项目数据.md`。

主要入口：

- `lib/main.dart` → `bootstrap.dart`（加载 SharedPreferences、构造
  `ProviderContainer`）→ `app.dart`（`MaterialApp.router` + GoRouter 路由表）。
- 所有 provider 在 `lib/state/`；不要在 `features/` 新建全局 provider。
- Agent prompt 只在 `lib/services/agent/agent_prompts.dart`；富文本后处理只在
  `lib/services/agent/rich_text_post_processor.dart`。

## 4. 主要数据流

1. **文本**：输入/剪贴板 → `MecabService` 分词 → `Token` 列表 →
   `features/reader` 渲染（注音/词性）→ 点击 token → `LookupGateway` →
   MDict worker → WebView 词条。
2. **照片**：相机/相册 → `CaptureStorage` 私有副本 → `OcrService`
   （Paddle 横向 / MangaOCR 纵向 / auto）→ `OcrTextComposer` → UniDic →
   reader/照片集 → 查词。
3. **Agent**：输入（文本/图片 OCR）→ 证据构建（UniDic/MDict/语法）→
   固定流水线 prompt → provider（OpenAI-compatible/Anthropic）→ 解析/校验/
   validator → 富文本后处理 → Agent 页/历史。图片只在本地 OCR，不上传。

## 5. 资源与构建

- OCR 模型：`assets/models/manifest.json` 只含清单；模型本体运行时下载/导入，
  SHA-256 校验，目录由用户配置。
- 字体：`assets/fonts/HarmonyOS_Sans_SC_Regular.ttf` 不入库，构建前按
  `assets/fonts/README.md` 放置。
- 用户数据：`unidic/`、`mdicts/`、`test_images/` 不入库。
- 签名：release 仍使用 debug keystore（`android/app/build.gradle.kts` TODO），
  分发前必须替换（R-DEV-05）。
- 版本号：`pubspec.yaml` 的 `version:` 是唯一来源；构建脚本不再另写一套
  `versionName`。

## 6. 维护约定

- 新增 >500 行 Dart 文件或新的跨 feature import，在 `代码盘点.md` 登记。
- 新增/移动文档必须更新 `docs/README.md` 并跑 `dart tool/check_docs.dart`。
- 不重写已验证的 Paddle 横向 OCR、MangaOCR 基础流水线、UniDic/MDict 核心路径；
  修改前先读 `04-历史/项目历史.md` 与对应阶段快照。
