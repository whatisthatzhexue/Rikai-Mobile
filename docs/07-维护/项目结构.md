## 1. 顶层结构

2026-11-14 起采用 **app / supabase / worker** 三产品分离结构。顶层只保留子项目
目录与仓库级文件；`docs/`、`tool/`、`third_party/`、`data/` 是仓库级支撑目录。

| 目录/文件 | 作用 | 状态/跟踪 |
|---|---|---|
| `app/` | Flutter 客户端唯一构建入口 | 已迁移；跟踪 |
| `supabase/` | 鉴权、社区、术语表同步；迁移/Edge Functions | [planned] 未创建 |
| `worker/` | Python Worker：调度/云 OCR/配置/遥测 | [planned] 未创建 |
| `docs/` | 跨子项目权威文档；入口 `docs/README.md` | 跟踪 |
| `tool/` | 仓库级编排：文档检查、verify | 跟踪 |
| `third_party/` | 第三方来源/许可/修改记录；不参与构建 | 跟踪；`upstream/` 忽略 |
| `data/` | 本地开发/用户数据；不打包 | 忽略 |
| `.claude/` | Claude Code 工具配置 | 跟踪/本机忽略 |
| `.gitignore` | 仓库级忽略规则 | 跟踪 |
| `README.md` | 人/Agent 总入口 | 跟踪 |
| `CLAUDE.md` | Agent 入口、命令白名单、禁令指针 | 跟踪 |
| `NOTICE` / `THIRD_PARTY_NOTICES.md` | 第三方许可与修改说明 | 跟踪 |

**迁移遗留**：`mdicts/`、`test_images/`、`overlay-translator/`、
`PaddleOCR4Android/` 目前仍在根目录且已忽略；目标位置分别为 `data/mdicts/`、
`data/test_images/`、`third_party/upstream/`。移动它们不需要改源码，移动后同步
`.gitignore` 与设备测试命令即可。

## 2. `app/` 子项目

| 目录 | 职责 | 边界 |
|---|---|---|
| `app/android/` | Android 宿主、Kotlin、Manifest、资源 | 只服务 App |
| `app/assets/` | 打包资源：模型清单、图标、许可、字体说明 | 模型二进制不入库 |
| `app/lib/` | App 源码：`core/`、`services/`、`state/`、`features/` | 不 import supabase/worker |
| `app/packages/` | 本地基础设施包与契约 | `rikai_ocr`、`mecab_for_dart`；`plugin_api` 为 planned |
| `app/plugins/` | 语言插件实现 | planned；只依赖 `plugin_api` |
| `app/test/` | 单元/widget 测试 | 不联网；fake provider |
| `app/integration_test/` | 设备/模拟器集成测试 | 性能场景在 `performance/`（planned） |
| `app/tool/` | App 专用脚本 | 仓库级编排不在本目录 |
| `app/pubspec.yaml` | App 依赖/资产/版本唯一来源 | 根目录不再有 pubspec |

`app/lib/` 四层：

| 层 | 职责 | 依赖规则 |
|---|---|---|
| `core/` | 纯模型、主题、通用 UI、工具 | 不依赖 `services/state/features` |
| `services/` | Agent、MDict、MeCab、OCR、存储、查词、安全 | 不导入 `features/state`，不依赖 Flutter UI |
| `state/` | Riverpod provider/controller | 可依赖 core/services |
| `features/` | 页面与 widget | 可依赖 core/state/services |

- 所有全局 provider 在 `app/lib/state/`；`features/` 不新建全局 provider。
- Agent prompt 只在 `app/lib/services/agent/agent_prompts.dart`；查词由
  `LookupGateway` 共享。
- `app/packages/rikai_ocr`、`app/packages/mecab_for_dart` 是本地 path 包；
  `rikai_ocr` 包名与 `RikaiOcr` 类名是兼容契约，改名需 ADR/迁移验证。

## 4. 主要数据流

1. **文本**：输入/剪贴板 → `MecabService` 分词 → `Token` 列表 →
   `app/lib/features/reader` 渲染 → 点击 token → `LookupGateway` →
   MDict worker → WebView 词条。
2. **照片**：相机/相册 → `CaptureStorage` 私有副本 → `OcrService`
   （Paddle 横向 / MangaOCR 纵向 / auto）→ `OcrTextComposer` → UniDic →
   reader/照片集 → 查词。
3. **Agent**：输入（文本/图片 OCR）→ 证据构建（UniDic/MDict/语法）→
   固定流水线 prompt → provider → 解析/校验/validator → 富文本后处理 →
   Agent 页/历史。图片只在本地 OCR，不上传。

## 5. 构建与验证

在仓库根目录：

```powershell
dart tool/check_docs.dart
dart tool/verify.dart
dart tool/verify.dart --build
```

Flutter 命令统一在 `app/` 下执行：

```powershell
cd app
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```

- 字体：`app/assets/fonts/KiyosunaSans/` 内置 KT Kiyosuna Sans Light/Bold；
  许可与署名见 `app/assets/fonts/KiyosunaSans/README.md`。
- 图标：修改 `app/assets/LexiCandy_Icon.jpg` 后在 `app/` 下运行
  `dart run flutter_launcher_icons`。
- 开发数据：`data/` 不入库、不打包；设备测试用 `--dart-define` 指向设备路径。
- 签名：release 仍使用 debug keystore（`app/android/app/build.gradle.kts` TODO），
  分发前必须替换（R-DEV-05）。
- 版本号：`app/pubspec.yaml` 的 `version:` 是唯一来源。

## 6. 维护约定

- 新增 >500 行 Dart 文件或新的跨 feature import，在 [`代码盘点`](代码盘点.md) 登记。
- 新增/移动文档必须更新 [`docs/README.md`](../README.md) 并跑
  `dart tool/check_docs.dart`。
- `[planned]` 目录（`supabase/`、`worker/`、`app/plugins/`、
  `app/packages/plugin_api/`、`app/integration_test/performance/`、
  `app/tool/perf/`、`docs/performance/`）未启用前不要创建或依赖；创建需人工确认。
- 不重写已验证的 Paddle 横向 OCR、MangaOCR 基础流水线、UniDic/MDict 核心路径；
  修改前先读 [`项目历史`](../04-历史/项目历史.md) 与对应阶段快照。
