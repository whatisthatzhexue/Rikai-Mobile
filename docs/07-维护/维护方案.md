# 维护方案（M-1 / M0 / M1）

> 状态：当前参考（维护方案）｜最后同步：2026-11-14

本文件把 `Review目标.txt` 的要求拆成可执行、可验收的维护工作流。原始需求见
`Review目标.txt`；实际进度与例外见 `版本命名.md`、`项目结构.md`、`代码盘点.md`。

## 1. 三个维护阶段

| 阶段 | 目标 | 验收 |
|---|---|---|
| M-1 | 建立不再人工重做维护的机制 | 单一文档入口、状态横幅、版本词汇表、自动检查脚本 |
| M0 | 整理文档/资源/结构，不改业务行为 | 文档链接 0 broken、assets 清理、架构地图完成、analyze/test/build 通过 |
| M1 | 按盘点分批修剪代码 | 每批 analyze/test/build + 对应设备回归 |

M0 本轮已批准执行；M1 只做盘点，不启动。产品阶段仍用 `阶段 N`；维护阶段使用
`M-1/M0/M1`，不得复用旧的 `Phase -1/0/1` 写法。

| M0-H | `check_docs` 完整规则 + `verify.dart` + 验证清单 + R-DOC-12…15 |

## 3. 文档规则

- 唯一入口：`docs/README.md`；新文档必须登记。
- 文件名中文、无空格/全角标点；技术文件名例外在 `docs/README.md` 登记。
- 每份文档有状态横幅：当前权威/当前设计/当前进度/历史快照/已废弃。
- 当前值只写一处：规则/数据/UI/契约/历史分层；历史文档不回填当前值。
- 版本写法见 `版本命名.md`；`Phase N` 仅英文别名，`P6.x`/`P7.x` 仅工作包。

## 4. 资源规则

- `app/assets/models/manifest.json` 保留清单/许可/URL/SHA；展示文案在
  `app/lib/core/models/ocr_model_copy.dart`，不在数据文件硬编码中文。
- `app/assets/agent/` 已删除：grammar/probes/word lists 改为 Dart 常量；词表 UI/导入/
  非日语 tokenizer 仍未实现。
- 字体/模型/词典/UniDic/API Key 不入库；release 签名仍是待办。

## 5. 验收

- `dart tool/check_docs.dart`：0 issue。
- `cd app && flutter analyze`：No issues。
- `cd app && flutter test`：全过；数量只记录在 `01-规范/项目数据.md`。
- `cd app && flutter build apk --debug`：成功，versionName/versionCode 与
  `app/pubspec.yaml` 一致。
- 版本审计：当前中文文档无旧写法的阶段/优先级/反馈波次标签；`P6.x`/`P7.x` 保留。
- 冒烟：主页 5 入口、阅读、查词、语料、设置、Agent 离线打开；OCR 模型页名称/
  许可不变。

## 6. 不做什么

- 不 commit/reset/push（除非用户明确要求）。
- 不重写已验证的 Paddle 横向 OCR、MangaOCR 基础流水线、UniDic/MDict 核心。
- 不把未实现能力（词表导入、完整 text/group DSL、真实 provider 验收等）写成已支持。
- 不在本轮启动 M1 代码修剪；只按 `代码盘点.md` 的批次排队。
