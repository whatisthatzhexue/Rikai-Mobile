# Rikai-Mobile 设计 Token 规范

> 版本 2.0 · 2026-10-30（Phase 6 Agent 对话式 UI 规范）
> 状态：**强制规范**。所有现有与后续 UI（含 Phase 2+）必须遵循本文件；
> 功能设计与 UI 设计同步进行时以此为准。
>
> 实现：`lib/core/theme/app_tokens.dart`（token）与 `AppTheme.light()`
> （Material 3 主题）。页面中不得硬编码颜色、字号、间距、圆角。

## 1. 视觉方向

- **蓝 / 白**：白色内容面 + 浅灰蓝页面底色 + 品牌蓝交互色。
- **紧凑直观**：4pt 间距体系，常规控件高 40dp，列表与卡片低留白。
- **阅读优先**：正文清晰、层级克制；不使用的装饰性阴影和大面积渐变。
  阅读器的阅读面、结果区与输入/分词/复制工具区**均为白色**；工具区底边为
  1px `divider` **浅色细线**（类似查词搜索栏下方），与结果区自然分隔，
  不改变工具区底色、不形成厚重色块。阅读器内不使用灰色文字。
- **平面分层**：1px 边框代替阴影；卡片白底、圆角 12。
- **单一光源**：每屏一个主操作（品牌蓝实心按钮），其余操作用描边/文字按钮。
- 当前版本**只提供浅色主题**；深色主题不属于 v1 规范，后续如需加入必须先扩展
  token 表，不得在页面里临时反色。

## 3. 字体与字号

- 字体家族：**HarmonyOS Sans SC**，Regular（400）。
- 资源路径：`assets/fonts/HarmonyOS_Sans_SC_Regular.ttf`。
- **字体文件不入库**：由使用者自行从华为 HarmonyOS 设计资源下载，说明见
  `assets/fonts/README.md`。构建前必须放置到上述路径，否则 Flutter 构建失败。
- 当前仅提供 Regular。层级通过**字号 + 颜色 + 留白**建立，不依赖多种字重；
  后续若加入 Medium/Bold，必须同步更新 `pubspec.yaml`、`app_tokens.dart` 和本表。
- 用户可在左侧抽屉的“自定义字体”中切换 **HarmonyOS Sans（内置）** 与
  **系统默认**；默认是 HarmonyOS Sans。字体文件不入库，见第 9 节。

### 3.1 字号组合（72 / 48 / 36）

设计稿按 **3x** 标注；Flutter 逻辑字号为设计 px ÷ 3：

| Token | 设计稿 | Flutter | 行高 | 用途 |
|---|---:|---:|---:|---|
| `AppTypography.display` | 72px | **24sp** | 1.25 | 首页主标题、空状态标题、词条页大标题 |
| `AppTypography.headline` | 48px | **16sp** | 1.5 | 正文、列表标题、按钮、输入文字、Tab |
| `AppTypography.title` | 36px | **12sp** | 1.5 | 极短标签/时间；不用于正文、设置说明、帮助/著作权 |

补充组件字号（不改变 72/48/36 主阶梯）：

| Token | 值 | 用途 |
|---|---:|---|
| `AppTypography.helper` | **14sp** | 设置/表单提示、列表副标题、搜索结果摘要 |
| `AppTypography.sectionHeading` | **18sp** | 帮助/著作权等长文页的栏目标题 |
| `AppTypography.entryTitle` | **24sp** | 查词结果词条标题（16sp 的 1.5 倍） |
| `AppTypography.homeAction` | **32sp** | 主页功能按钮（居中；比首版 40sp 小 20%） |
| `AppTypography.ocrPreview` | **20sp** | 多选页缩略图内的 OCR 预览文字 |

> 注意：72/48/36 是 3x 设计稿标注，不是 Flutter 直接使用的 sp。移动端直接使用
> 72sp/48sp/36sp 会破坏布局，禁止。

- 标题/按钮使用 16sp 与语义色；24sp 用于页面级重点和查词结果词条。
- 正文不得低于 16sp；设置/表单的灰色提示统一 14sp，且必须允许换行，
  **禁止出现省略号或显示不全**。
- 12sp 只用于极短标签；不要用于设置说明、帮助/著作权正文或搜索结果。
- 默认 `letterSpacing: 0`；中文标签不使用负字距。

### 3.2 阅读区字号（内容例外）

阅读区正文是用户可调内容，不属于 UI chrome：

- 范围 14–30sp，默认 **20sp**（`AppTypography.readerDefault`）。
- 行高 1.6；振假名字号为主字号的 **55%**（`furiganaRatio`）。
- 标点/空白不显示注音。
- 阅读面、结果列表与输入/分词/复制工具区**均为 `surface` 白色**；工具区
  底边为 1px `divider` 浅色细线（对齐查词搜索栏下方的处理）。输入框
  `filled: false`，不额外铺白色块；工具区高度紧凑，白色底上只保留这条
  浅色收边，长文滚动时不得出现厚重色块分区。
- 内容词：蓝50背景 + 蓝700文字；功能词与标点：透明背景 + `textPrimary`
  （近黑）；振假名：品牌蓝 `primary`。**不得在阅读器内使用灰色文字**；
  以蓝色/黑色/字重建立层级，减少视觉刺激。

### 3.3 词典 WebView

- 词条正文：白色背景、`font-size: 16px`、`line-height: 1.7`、页面内边距 16px。
- 保留词典自带 CSS；图片 `max-width: 100%`。
- 应用外壳（AppBar、Tab）使用本 token；WebView 内容保持词典原貌。

## 5. 组件规范

### 布局原则（强制）
- **禁止组件套组件**：输入框、按钮和提示文本直接放在页面/分栏上，
  不要包在带边框的 Card/Container 里（UniDic 目录栏是反例，必须保持扁平）。
- 设置页采用白底扁平分区：分区标题 → 分隔线 → 控件；整组设置不再用卡片包裹。
- 只有可点击的内容列表项（如查词结果）使用卡片；卡片内不得再套卡片。
- 长提示文本必须独立成 `Text`，放在控件下方并允许换行；不要依赖
  `InputDecoration.helperText` 的单行显示，禁止省略号/截断。
- 用户不可变的信息（如应用外部私有目录路径）用 16sp 纯文本展示，
  不使用卡片或输入框。
- 页面左右边距 16；分区之间用 24–32 的留白和分割线区分。

### 页面转场（强制）
- 所有路由（go_router 与 `Navigator.push`）统一使用
  `SlideOverPageTransitionsBuilder` / `RikaiPageRoute`：新页面从右侧滑入并
  覆盖旧页面，旧页面保持原位，不做淡出、缩放或上滑淡入。
- 通过全局 `ThemeData.pageTransitionsTheme` 与 `RikaiPageRoute` 设置，页面
  不得自行定义转场；这样深蓝顶栏导航时不会出现白色残影/白色瑕疵。
- 退出页面为同一动画的反向播放。底部弹层、对话框保持系统自身的弹出方式，
  不属于页面转场。
- 进入 220ms、退出 180ms；不要恢复 300ms 默认值。词条 WebView 在 reverse
  开始时脱离绘制，避免 platform view 在退出瞬间回闪。
- go_router 路由使用 `CustomTransitionPage` 保持相同的 220/180ms 与滑入曲线。

### AppBar（全局统一）
- **所有页面**（主页、阅读、设置、查词、词条、词典、帮助、著作权）统一使用
  深蓝 `#003A99` 背景、白色标题/图标，无底部分割线；状态栏图标为浅色。
- 高 52，标题 16sp/600；图标 20。主页标题居中，其余页面标题左对齐。
- 不使用 elevation/滚动阴影。
- 词条页的 TabBar 位于深蓝顶栏内：白色选中标签与白色指示器，未选中 72% 白。
- 抽屉顶部同为深蓝背景、应用图标与白色文字；**抽屉本体为直角**，不使用圆角。

### 主页功能按钮
- 页面按 Column 顺序排列：顶部「使用前须知」卡片 → 五个功能按钮 →
  初学者友好的「边界说明」卡片（OCR 可能漏字/认错，UniDic 按短单位分词、
  复合词读音不一定完全准确）。
- 不再把按钮在剩余空间中垂直居中；小屏时整体可滚动，不得溢出。按钮区不因
  卡片增加而改变样式。
- 五个全宽实心按钮：拍照识别、查句子、查单词、历史记录、词典助手。
- 背景色与顶栏相同：`AppColors.header`（`#003A99`），白色图标与文字。
- 高度 72，圆角 12，图标 28；**图标与文字作为整体居中对齐**。
- 文字 32sp（首版 40sp 的 80%）、行高 1.35，600 字重。
- 不使用副标题；按钮之间的间距为 12。

> **Phase 6 状态**：P6.5 已把主页改为五个按钮（拍照识别、查句子、查单词、
> 历史记录、词典助手），并接入 Agent 页、严格/宽松选择、来源 chip 和 provider
> 设置。下方“四按钮”历史规则只用于理解旧版；当前以“Phase 6 Agent UI”与自查清单
> 为准。P6.6/P6.7（多 OCR、Markdown/ruby/声调）仍需补 token/测试。

#### Agent 对话式界面 v2（设计规范；基础已实现，逐项验收）

> 本节把通用 AI 对话 UI 规则融入 Rikai 的蓝/白体系。与上文或全局规范冲突时，以
> 上文为准：正文 16sp（不是 14sp）、仅浅色主题（暗色后续扩展）、输入框白底 8 圆角
> （不是 surfaceVariant/20）、AppBar 52（不是 48–56）。当前 P6.5 已实现基础
> 对话式布局（气泡/流式/折叠依据/固定输入区）；状态条、历史、无障碍 200% 等
> 完整 v2 验收项仍待补，未完成项不得写成已支持。

**视觉原则**

- 对话为主体：正常竖屏首屏约 80% 高度给消息区（小屏/横屏可降到 70%，配置仍
  默认收起）；provider/model/会话词典/熟悉期等配置收进顶部“本会话设置”展开面板
  或二级设置页。
- 状态可见：等待、生成中、失败、降级、离线都有图标/颜色/动画/文字中的至少两种，
  不只靠文字。
- 错误不吞内容：失败保留已生成文本与证据；错误以消息内卡片出现在下方，不弹全局
  对话框、不整屏 loading。
- 可追溯：AI 消息底部折叠“依据 N 条 ▾”；展开后按词典顺序显示来源名/摘要/
  citation；严格模式无依据时显示“无词典依据”，不隐藏。
- 流式：首个 token 前显示阶段文字 + 三点动画（≤3 秒）；之后逐字/逐块追加，尾部
  光标闪烁；不显示整块“正在输入…”。

**布局**

| 区域 | 高度 | 规则 |
|---|---:|---|
| AppBar | 52 | 深蓝 header 白字白图标；标题左对齐；新会话/历史/设置 20dp 图标；模型/模式 14sp 标签放标题下方或状态条。 |
| 本会话设置 | 可见 32 / 触控 ≥40 | 一行“本会话设置 · 严格/宽松 · 模型简称”；点击展开或底部 sheet；包含会话词典筛选、严格/宽松、模型路由。首屏默认收起。 |
| 状态条 | 24–32 | 可选；surfaceMuted 底、14sp；显示“生成中/已降级/离线”；不覆盖消息。 |
| 消息区 | 剩余 | 可滚动；左右 16、消息间距 12；用户右、AI 左；最大宽 80%；底部留 composer 高度 + 安全区；长代码/表格横向滚动。 |

**消息气泡**

- 用户：`agentUserSurface`（blue50）+ `textPrimary` 16sp；圆角 16、右下 4；右对齐；
  不显示头像/时间戳（长按才显示时间）。
- AI：`agentAssistantSurface`（surface 白）+ `textPrimary` 16sp；圆角 16、左下 4；
  顶部 12sp `agentModelLabel`“模型名 · 严格/宽松”，点击打开模型/模式切换 sheet；
  不显示整块“正在输入”。
- 系统/工具：居中、14sp `textSecondary`、无气泡；用于“已切换严格模式”“词典档案
  已更新”等，不打断对话流。
- 气泡内边距 12–16；消息间距 12。
- 消息最大宽 80%；字号放大到 200% 时允许 90%，仍禁止满宽。长代码/表格/引用块
  横向滚动，不撑破气泡。
- 操作行：完成后从左到右显示循环（重新生成）/复制（Markdown）20dp 图标，
  40dp 触控，带 `Semantics`；用户气泡长按提供复制/修改。
- 错误卡：AI 消息下方独立卡片，`agentErrorCard`（surface + error 图标/1px 边框），
  14sp 原因 + 一个主操作；已生成内容保留。

**证据块**

- 默认折叠：AI 消息底部一行“依据 N 条 ▾”（14sp primary，`agentEvidenceCollapsed`）；
  N 为本次 citation 数。
- 展开：按 `dictionaryOrder` 分组；词典名 16sp/600、词条 16sp、摘要 14sp
  textSecondary、citation chip 28/12；点击 chip 打开词条。
- 严格模式无依据：14sp textSecondary + warning 图标“无词典依据”，不隐藏、不伪装
  成事实；宽松模式模型补充继续用独立“模型补充”标签。
- 证据卡片沿用 `agentEvidenceSurface`/`agentEvidenceBorder`/`agentEvidenceRadius`；
  不把证据塞进 Markdown 链接，不执行 HTML/JS。

**状态**

| 状态 | 视觉表现 |
|---|---|
| 空闲 | 输入框可用，发送按钮正常。 |
| 提交中 | 用户消息立即上屏；AI 气泡显示三点动画（≤3 秒），不整屏 loading。 |
| 流式生成 | 文本逐字/逐块出现，尾部光标闪烁，发送按钮变停止图标。 |
| 生成完成 | 光标消失，出现循环（重新生成）→复制（Markdown）操作行。 |
| 生成中断 | 保留已生成内容，下方 14sp textSecondary“生成中断 · 重试”。 |
| 降级 | 状态条或消息内 14sp warning“已降级为本地组合结果”，并说明原因。 |
| 离线 | 输入区上方常驻状态条“离线模式，仅本地功能可用”；Agent 发送禁用并说明。 |
| 错误 | 消息内错误卡：原因 + 一个主操作；不弹全局对话框。 |

**视觉禁止**：全屏 loading、阻塞式弹窗、无原因的错误提示（只写“出错了”）、
气泡满宽、生成中整块“正在输入…”占位。

**输入区**

- 占位文案：“输入问题，或粘贴文本…”（≤20 字）。
- 左附件/拍照图标 24；右发送圆形 40；禁用时透明度 35%（沿用 §按钮 禁用规则；
  模板的 40% 不采用）；生成中发送变停止方形。
- 单行起，最高 5 行后内部滚动；发送按钮位置固定，不随行数移动；键盘弹起时上推。
- 输入框白底、1px border、8 圆角、聚焦 1.5px 品牌蓝（沿用全局输入框规则；不采用
  模板的 surfaceVariant/20 圆角）。
- 间距 4 的倍数；输入区顶部 1px `divider`，不形成厚重色块。
- 附图时显示 64dp 缩略图 + 移除按钮；图片只在本机 OCR，不显示路径。

**设置页**

- 入口：Agent AppBar 右侧设置图标；分组顺序：模型/Provider → 语言 → 数据与隐私 →
  关于。
- 每个配置项：标题 + 一行说明 + 控件；危险操作（清除数据、删除 Key）二次确认。
- API Key：密码框 + 显示切换 + “测试连接”；测试结果就地显示成功/失败原因。
- 配置状态用“已配置/未配置/无效”三态标签，颜色 + 图标区分，不用开关混淆。
- 设置页沿用白底扁平分区、无卡片；长说明 14sp 完整换行。

**无障碍与主题**

- 正文 16sp、辅助 14sp、12sp 只用于短标签；行高 ≥1.5（阅读区 1.6）。
- 所有图标按钮、citation chip、消息操作有 `Semantics(label:)`；触控 ≥40×40。
- 对比度正文 ≥4.5:1，大字号 ≥3:1；错误/状态不能只靠颜色。
- 系统字体缩放至 200% 不截断；气泡最大宽度随字号自适应（80% → 90%）。
- 当前仅浅色主题；暗色模式的 #121212 等规则不纳入 v1，后续扩展 token 后再实现。

**动效**

- 消息出现/状态切换 150ms；证据展开/收起、错误卡出现 250ms；页面转场仍按全局
  220/180ms；不使用整屏缩放/弹跳。

  `textTertiary` 单色条以保证可见），剩余空间交给分词结果。

  “重试”；不得占用/排挤 OCR 结果区域。未配置 UniDic 的说明可留在结果区。
- 照片右下角的复制按钮文案统一为**「复制文本」**（`PhotoCopyButton` 默认值），
  样式为深蓝 `header` 长条按钮（白字白图标），有 OCR 文本后可用；标题栏只保留
  字号/注音菜单和“多选”。语料预览卡片右下角的复制按钮仍用较短的「复制」。

  不得单独发明第二套字号控件。

- 多选页：网格缩略图使用 `BoxFit.contain`，OCR 预览字号至少
  `AppTypography.ocrPreview`（20sp），复选框/已选数量；删除/保存沿用

- 识别结果按“照片 + 模式 + 模型指纹”缓存，模式为会话级；从模型设置、多选页

## 9. 字体获取

字体不在仓库中。构建前：

1. 从华为 HarmonyOS 设计资源下载 HarmonyOS Sans（SC Regular）。
2. 放置为 `assets/fonts/HarmonyOS_Sans_SC_Regular.ttf`。
3. 运行 `flutter pub get` 与构建；缺失时构建会报 asset 错误。

详见 `assets/fonts/README.md`。字体由使用者自行下载，项目不再分发。
