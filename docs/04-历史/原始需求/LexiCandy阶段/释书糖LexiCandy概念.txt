名称：释书糖 / LexiCandy
寓意：致敬“物书堂”，寓意像吃糖一样轻松啃下原版书。
简介：一个本地优先、证据可追溯、可定制的外语深读与写作工作台
核心环绕功能：
分词器(UniDic等) + MDict(我们不再引入其他格式词典，单格式保持词典设计一贯性) + OCR(MangaOCR等) + Agent(初期接LLM api，后期可加入端侧小模型)
架构思考：
前端：Flutter（负责极速渲染、丝滑状态机、端侧 OCR/字典/分词器管线）。
用户数据：Supabase（负责用户鉴权、社区数据、术语表同步，不碰核心推理）。
调度端：Python Worker（轻量调度器+云端OCR，只回传 Action、OCR 结果、动态配置分发，可收集用户日活/失败案例/未命中词典/部分元数据，注意信息脱敏）。
开发主线说明：
日语只是我们的落脚点和调研出发地，但外语学习的模板思路在设计上可以互通，这就是多语学习者为什么能存在的基础
项目架构未跑通前（甚至可能一直到决赛，我们都只有日语功能是最完善的），我们只做日语场景下的现代书籍阅读。但是工程上需要一开始就留好通用功能接口，便于后续快速扩展到其他语种如英语。
初期针对日语场景，深度优化日语OCR在手机上对竖排、弯曲、反光的处理，做到真正的“拍书即读”。
开发宗旨：
所见即所点：以OCR为中心，避开强迫用户进行繁琐的词典搜查/手动输入句子操作，多引导用户在OCR识别结束的图片上，通过页面简单点击/滑动，调用出多窗口内容 + Agent解析，实现学习效果。（写作模块除外）
万物皆可溯：任何一个 AI 生成的结论，点击即可高亮原图或原句。
软件变身：学习用户习惯，给予用户学习快照，可高度自定义，点击即可回到上次的学习场景/页面（避免用户回退到专业工具如辞书软件）
个人成长：后台离线静默记录用户的学习内容。用户可划取时间段，让端侧或在线模型分析个人成长，对抗容易遗忘的知识
零配置前台，极客后台：普通用户永远看不到配置项，极客用户能通过深层设置找到高级面板。
项目定位限制：
强调实体书资产在当代的重要性。
“可定制的深读”。我们不是翻译器，我们承载用户的思考。通过“阅读-写作-社区”的闭环，让用户从“看懂世界”进化到“发出声音”。
实体书精度慢而深，啃游戏生肉快而浅，因此我们不做应用外悬浮窗，并希望用户能在应用中获得沉浸式深度体验
隐私收集 + 内容本地/端侧/云端必须写明，便于向企业视角过渡。
PDF只简单做基本文字提取，核心叙事中心与竞争力在外文图书OCR。
界面原则：
做好细粒度（语境->句->词）拒绝给用户灌输过多信息（拒绝信息过载）
工程原则：
引入插件系统，以“插件”形式提供多语种/多场景支持
语言特性的差异是巨大的（日语有振假名和复杂的活用，英语有词根词缀和短语动词，法语有阴阳性，德语有格位变化）。如果硬把它们塞进一套固定的代码逻辑里，后期绝对会变成无法维护的 if-else 屎山
预期所有的语言规则无一例外编码为文件，这样语言变迁后，改改文件还能用。支持可空字段。
要支持新语言，只需要上架一个新的语言插件即可
其余技术细节，参见“项目成熟化处理.txt”
更多场景：
教师端——支持手机在局域网上开放端口，实现App阅读精解内容投放到电脑网页（不做机械的画面上传，而是阅读数据在web端的重新设计排布）方便教师教学或远程演示。
面向企业：开放企业模式，该模式下侧重本地处理，杜绝数据上云端OCR，减少使用Agent API，保证数据隐私。
4个页面
①阅读（Read）：沉浸式解构
可阅读app内置电子书/用户实体书的OCR/纯文字PDF
首次启动：无需配置，直接展示预存的示例实体书与解析效果，引导用户拍下第一张实景照片。
用户可在创建书籍时选择竖写排版或横写排版
阅读过程中能做波浪线、高亮批注（降低决策压力，同时保留用户阅读时的思维涌现）
支持知识（细粒度：词，优先本地搜索匹配词条，可询问Agent语境义） / 理解（细粒度：句/语境，优先跑分词器结构分析，支持Agent句间分析和句内分析） / 读音（细粒度：句/语境，读音讲解，从词典和分词器尽可能获取权威的读音信息，可询问Agent整体读音）三种知识解答模式
点击句子，不仅弹出该句读音（当语言为日语时），还弹出一个操作小气泡，气泡中有3个Tab 知识 / 读音 / 理解
段落有显式“总结”按钮，Agent输出若干语境相关的备选项供用户点击。用户点击后即可展开该备选项（备选项含“我想创建术语库”，走独立流程），并开始生成相应的Agent解答。
术语库：边读边长按标记“文化梗/专有名词”，即时生效。通过用户上传术语库，允许用户借此上传动漫/影视剧特定的文化知识，内容责任需要明确声明属于用户，需要注意内容侵权问题。术语库支持“防剧透内容折叠”。
结构三级平面图（批注式 UI）：
  · 第一层（句）：原书照片的 OCR 重叠排版，无感翻页。
  · 第二层（词/语法）：点击即可弹出本地 MDict字典与分词器分词结构，所见即所点。
  · 第三层（知识关联）：展示句子关系图、音调读法表、以及可溯源的 Agent 解析。
②写作（Write）：无打断的生产
丝滑切换：从阅读页一键滑入写作。反过来，也可以从写作页一键滑入阅读页。App生命周期内，阅读和写作页各自缓存自己的当前内容。
本功能旨在鼓励用户表达自己的读书感想或语言收获。Agent动态关注输入状态，每次用户的句子闭合，触发一次分析。可有如下结果：你的助词一开始用的是对的，后来改错了……你看**词典中关于**的义项……。用GitHub的思路做用户diff，完事还能把自己的思考流发布社区。
当用户按下“开始撰写感想”，即按照“最近的批注->最近的书（用户阅读进度客观数据 + 读到的内容节选）->日常练习(预制问题，不走Agent除非用户要求)”的顺序，生成写作引子（即一个相关问题），写作引子会自动作为新文章的标题（用户也可以后续自行修改标题）
用户可切换竖写排版或横写排版
写作过程中能做多颜色框选、波浪线、荧光笔批注
写作过程中，用户可以自由选择 OCR / 手写(实质也是OCR) / 手动输入 三种方式添加内容。默认使用用户系统键盘。App提供App内置输入法，外语写作不必须自备输入法，允许用户切换在自己的输入法和应用输入法之间切换。
App内置输入法：不走Agent。依赖现有资源 / 云端资源。以词典 + 分词器为权威信息源。日语模式下支持罗马音+拼音混合输入，自动模式下app会自动根据词典搜索结果以及分词器信息判断罗马音/拼音，然后给出可能的输入法候选（当判断为拼音时，中文候选结果上方还会弹出对应词的对应语种翻译结果），长按单词还会出现变形活用候选。
内置输入法最小支持：布局26键，支持纯日语和中日模糊语种输入。
内置输入法三大支柱：支持手动输入分词符 / 支持模糊语种(视语言[插件]而定，即可以同时打罗马音和拼音或英文和拼音等等) / 支持输出变形后的动词（变形规则视语言[插件]而定）
AI 差异教练：静默记录用户的写作草稿，按句子闭合触发分析，用 GitHub 风格的 Diff 展示语法纠错和词典依据。
③社区（Community）：语境化分享
用户可以在社区发布自己的 写作批注历史 + Agent解答结果，也可以在社区发布自己的书籍术语库。
风险兜底：敏感词库，被举报（非恶意举报）的内容走一遍AI质检（由worker+开发者自己的key完成），防止内容出问题
主题文章：分享自己的精读批注、语法推敲轨迹。
社区术语表（防剧透折叠）：用户发布的特定作品术语包，后来者拍书即可一键加载。解释内容默认折叠，防止剧透
④个人（About Me）
界面上到下分别有：成长曲线、学习快照、设置
学习快照：一键回到上次阅读的特定页码与状态。
成长曲线：后台静默记录生词与语法，按周生成词汇覆盖度报告。
